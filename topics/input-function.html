Python: Taking User Input & Type Conversion

The input() function always hands you back a string — even when it looks like a number. This is where that quietly breaks your math, and why.

Overview

This topic covers Python's built-in input() function — how it works, how to use prompts with it, and (most importantly) the fact that input() always returns a string, no matter what the user types. This has real consequences when you try to do arithmetic on user input, which is demonstrated with a "number concatenation" bug.

Key Concepts

  • input() reads a line of text from standard input (keyboard) and returns it as a string.
  • The prompt message can be passed either positionally or as a keyword argument (prompt=).
  • Even if the user types digits (like 56), Python stores it as a string '56', not an integer.
  • Using + on two input strings concatenates them instead of adding them mathematically.
  • type() is used to check the data type of any variable or value.

Detailed Explanation

1. Basic input() — no prompt

input()
  • Running this pauses execution and waits for the user to type something, then press Enter.
  • Example: user types 56 → the cell returns:
Out[1]: '56'
Note: Even though 56 looks like a number, it is returned as the string '56' (notice the quotes in the output).

2. Using a prompt message

You can pass a custom prompt so the user knows what to type:

input("Apna naam bata")
  • Output while waiting: Apna naam bata (cursor waits right after this text for the user to type)
  • User types: Nitish
  • Result:
Apna naam bataNitish
Out[1]: 'Nitish'
Note how the prompt text and the user's typed input appear on the same line — input() does not automatically add a space or newline after the prompt.

The same can be written using the keyword argument form:

input(prompt="Apna naam bata")

Produces the identical result: Out[1]: 'Nitish'

3. The "string concatenation" trap with numeric input

This is the most important gotcha demonstrated in this lesson.

first_num = input("Enter the first number")   # user enters: 56
second_num = input("Enter the second number")  # user enters: 76

print(first_num)   # 56
print(second_num)  # 76

Now, adding them:

result = first_num + second_num
print(result)

Output:

5676
⚠️ This is NOT 56 + 76 = 132. Since first_num and second_num are both strings ('56' and '76'), the + operator performs string concatenation, not addition — so '56' + '76' becomes '5676'.

This demonstrates why you must convert input to the correct type (e.g., using int() or float()) before doing math with it — showing the fix, this is the natural next step (type conversion).

Commands / Syntax Summary

# Basic input, no prompt
value = input()

# Input with a prompt (positional argument)
value = input("Enter something: ")

# Input with a prompt (keyword argument)
value = input(prompt="Enter something: ")

# Checking type
type(value)   # always returns <class 'str'> for input()

Important Points

  • input() always returns a string, regardless of what the user types (numbers, True/False, etc. all become plain text).
  • To use the input as an actual number, you must explicitly convert it — e.g. int(input("Enter a number")) (this is the natural next lesson: type conversion).
  • + on strings concatenates; it does not add numeric values unless both operands have first been converted to int/float.
  • The prompt parameter of input() can be passed positionally or by keyword (prompt=) — both work identically.
  • Use type() any time you're unsure what data type a variable actually holds — don't assume from appearance alone.
  • input() needs an interactive frontend; it will error out in non-interactive/unsupported execution contexts.

Things to Remember

  • input() reads from the keyboard and always gives back a string.
  • Prompt text can go inside input("...") or input(prompt="...") — same result.
  • Classic beginner bug: input() + input() on two "numbers" glues them together as text (e.g., "56" + "76" → "5676"), it doesn't add them.
  • type() is your tool to double-check what type a value really is — don't trust appearances (a number-looking string is still str).
  • Fixing the addition bug requires converting the string to a number first (e.g., int()), which is the natural next topic after this one.
